不用把 32 节学完，按模块对着补

你不是「零基础」，是会语法但没做过工程。所以补法不是从头刷课，而是： 每个模块开课前，先花 1–2 小时把这张表上标出来的那几节过一遍，剩下的遇到再回查。 每张卡片右边的数字就是基础预备的节号，点下去直接跳到那一节。

最省力 · 3 天 只补到能开模块 1 第 20、21 节（Docker + compose）+ 第 8 节（脚本写成 CLI）+ 第 16 节（建表与写入）。够跑通第一个管道。
稳一点 · 一周 上面 + SQL 分析型那一段 加第 10、11、13、14 节（JOIN、聚合、窗口、NULL）。模块 3 之后全靠这几节撑着。
完整 · 两周 32 节按四块走完 再把概念块（25–32）通读一遍。不追求记住，混个脸熟，看视频不懵就够了。

七个模块，各自要衔接什么按开课顺序排

01

容器与基础设施即代码

Docker · Postgres · Terraform
这一模块你会做

用 Docker 起 Postgres，用 Python 脚本把 taxi 数据灌进去，再用 Terraform 在 GCP 上建 bucket 和 BigQuery 数据集。

先补这几节
20Docker 心智模型 21Dockerfile 与 Compose 08脚本写成人能维护的样子 16建表、写入与事务
没补会卡在：容器起来了但 pgAdmin 连不上——因为连的是 localhost:5432 而不是宿主机映射出去的端口； 两个容器互相访问时写了 localhost（应该写 compose 里的服务名）；数据没挂 volume，容器一删全没；GCP 项目没开结算，Terraform 建不动。
最小可用（两小时能拿下）

docker run -d --name pg -e POSTGRES_PASSWORD=root -p 5433:5432 postgres:16 → docker compose up -d → 用 psql 连上去建一张表、COPY 进一个 CSV。这三件事会了，模块 1 的视频就能跟着做。

02

工作流编排

Kestra
这一模块你会做

把「下载数据 → 转格式 → 灌库」写成 flow，加调度、加依赖、跑一次回填。

先补这几节
23YAML 与配置文件 32编排与调度 08脚本写成人能维护的样子
没补会卡在：YAML 缩进错一个空格整份 flow 起不来；{{ }} 变量插值和 shell 的 $ 混着写； 调度时间差 8 小时（容器默认 UTC），以为是 bug 其实是时区；回填时不知道哪天的数据已经跑过。
最小可用

能写一个含 3 个 task 的 flow，先用「手动执行」跑通，确认每步产物落盘，再挂 schedule。别一上来就调 cron。

03

数据仓库

BigQuery
这一模块你会做

建分区表 + 外部表，用最少的扫描量查最多的数据，理解为什么列式存储快。

先补这几节
28分区、文件布局与列式存储 13窗口函数 15索引与执行计划 14NULL 与三值逻辑
没补会卡在：一次 SELECT * 把免费额度烧掉一大截；分区字段用 STRING 存日期，导致分区裁剪失效； COUNT(字段) 和 COUNT(*) 结果对不上（NULL 在作怪）；忘记加 WHERE 限制分区。
最小可用

会写 CREATE TABLE ... PARTITION BY DATE(tpep_pickup_datetime) AS SELECT ...，并且知道「先看扫描量预估再点运行」。

04

分析工程

dbt
这一模块你会做

把一堆 SQL 拆成 staging / core / mart 三层模型，加测试、加文档、生成血缘图。

先补这几节
12子查询与 CTE 26从三范式到星型 27分层：为什么分好几层 23YAML 与配置文件
没补会卡在：不写 CTE，一个模型套五层子查询，自己都读不懂；不知道 ref() 是在建依赖图， 还在用表名硬连；测试挂了分不清是数据脏还是 SQL 逻辑错。
最小可用

三层各写一张模型（stg_ → int_ → fct_/dim_），中间全用 CTE，跑 dbt build 能过。

05

数据平台

Bruin
这一模块你会做

把摄取、转换、质量检查串成一条能重复跑的 pipeline，部署到 BigQuery 上。

先补这几节
01虚拟环境与包管理 02文件、路径与编码 30数据质量与数据契约
没补会卡在：Python 项目结构乱，import 找不到模块；路径写死成 C:\Users\... 换台机器就崩； 质量检查只写了「不为空」，不知道要检查唯一性、范围、及时性。
最小可用

一个项目里能跑通 ingest → quality → publish 三段，路径全用相对路径或配置项。

06

批处理

Spark
这一模块你会做

用 DataFrame 和 Spark SQL 处理百万级数据，理解 groupBy、join 背后的 shuffle。

先补这几节
06pandas 入门 07pandas 进阶：连接与内存 28分区、文件布局与列式存储
没补会卡在：Windows 上跑 Spark 缺 Hadoop 的 winutils（或用 WSL 绕开）；driver 内存爆了不知道要调 spark.driver.memory； 把 pandas 的写法硬套 Spark，忘了它是惰性求值，报错行号和出错地方对不上。
最小可用

读 parquet → groupBy 聚合 → 和一个维表 join → 写回 parquet，全程不 collect 到本地。

07

流处理

Kafka · Kafka Streams
这一模块你会做

起 Kafka，写 producer / consumer，用 Avro 定义 schema，做一次实时聚合。

先补这几节
05CSV / JSON / Parquet 20Docker 心智模型 29幂等、增量与重跑
没补会卡在：consumer 连不上——bootstrap.servers 在容器里写 localhost； 消息体格式前后不一致，消费端反序列化直接崩；重复消费不做幂等，重跑一次数据翻倍。
最小可用

producer 往 topic 发 JSON，consumer 打出来；能看懂 advertised.listeners 为什么要配。

★

毕业项目

端到端 · 2–3 周
要交什么

自选数据源 → 摄取 → 仓库分层 → dbt 建模 → 仪表盘，附 README、架构图、可复现的启动方式。

先补这几节
19Git 最小可用集 21Dockerfile 与 Compose 27分层 29幂等、增量与重跑
没补会卡在：项目跑在自己电脑上，别人 clone 下来起不来（没有 compose、没有 .env.example）； 提交历史一团乱，看不出做了什么；没有幂等，重跑就重复插入。
最小可用

README 里三条命令能从零跑起来：git clone → docker compose up → python pipeline.py。

可以放心跳过的别在已经会的东西上花时间

你有 Python 和 MySQL 底子，这几节扫一眼讲义、确认没有陌生名词就跳： 第 1、2、3 节（venv / 路径 / 异常，写过程序就会）、第 10、11 节（JOIN 与 GROUP BY，MySQL 里用过）。 唯一值得停一下的是第 13 节窗口函数——它不在「基础 SQL」里，但 dbt 和数仓里天天用。

所以现在该做的：打开模块 1 的视频，遇到看不懂的地方回这张表查对应节； 而不是先把 32 节刷完再开课——那样大概率刷到第 12 节就没劲了。
进度都在总台统一看：hub.html。
